# Internal Workflow: Governance Adoption by Product

1. Identify Product’s current pinned Governance commit and candidate target.
2. Review intervening accepted changes and Product impact assessments.
3. Check implementation changes, conformance updates, relevant tests, and documented incompatibilities.
4. Recommend adopt or defer; developer decides.
5. If approved, update the submodule pointer only. Do not edit Governance through the submodule and do not commit.
