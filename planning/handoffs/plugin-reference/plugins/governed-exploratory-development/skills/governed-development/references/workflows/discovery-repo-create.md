# Internal Workflow: Discovery Repo Creation

1. Confirm Local Project Configuration, portable Governance identity, and destination. Offer the writable Governance checkout's HEAD as the revision default; confirm and freeze the exact commit. Product's pin stays independent.
2. Interview for Full/Curated Governance Reading Scope, Discovery Type, framing, Product access, charter, and optional comparison. Explain that the complete submodule remains present and Curated controls agent reading.
3. Enumerate paths and inspect minimal authority metadata source-wide before body reads. Resolve supersession and identify Constitution paths. In Curated mode, record each path's relevance, benefit, risks, and explicit allow/exclude choice; always allow Constitution and exclude unlisted bodies. Surface unknown exposure for developer classification. Never inspect excluded bodies to make recommendations.
4. Bind the approved scope to the source identity and commit. Check compatibility with Product Access Mode. Validate all approved inputs before reserving the next DISC ID.
5. Create the minimal local Repo, initialize `.governance/` at the chosen commit, and generate `AGENTS.md`, `DISCOVERY.yaml`, and `GOVERNANCE-READING-SCOPE.yaml` outside the submodule. Contract-aware exports belong under `.contracts/`.
6. Configure only the required local Governance submodule connection; stage only `.gitmodules` and its Governance Git link. No Discovery commit, Product remote, push, or hosting action is allowed.
7. Validate schemas, source identity, exact pin and clean Git state, reading-scope agreement, minimal scaffold, and access boundaries. Preserve and report unexpected edits without overwriting or resetting them.
8. Show staged submodule changes separately from unstaged generated files. Explain that the pin becomes committed with the developer's first commit and that fresh clones must initialize the submodule from an available Governance source.
